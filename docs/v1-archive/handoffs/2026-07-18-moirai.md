## 1. How to think — the operating epistemics

These are not style preferences. Every one of them was earned by a concrete
failure or near-failure in the previous sessions. Violating them produces
exactly the silent errors this project exists to prevent.

### The epistemic core (the soul — internalize these first)

1. **An unenforced convention is a hope, not a safeguard.** If correctness
   depends on someone remembering a rule, the design is wrong. Make the
   mistake structurally awkward or impossible. (Origin: the sweep initially
   registered 280 separate hypotheses, which would have silently made every
   point look like N=1 to the DSR forever.)
2. **A "conservative" assumption with an unchecked direction is a bias,
   not a margin.** The 10bps slippage guess was defended as conservative
   for months. Measured: real impact is ~0.1bps. The guess was a
   false-negative generator that inflated the cost hurdle ~75%.
   Always ask: conservative *in which direction*, and *who checked*?
3. **N counts search, not executions.** The Deflated Sharpe's N is the
   number of looks at the data that could have changed which strategy you
   selected. Verification runs (walk-forward windows, cost stress, null
   benchmarks, Monte Carlo) can only kill a candidate, never select one —
   they are not search. This distinction is now enforced in code
   (`RunKind`), and any reasoning that conflates the two is wrong.
4. **The record is the source of truth; never duplicate state.** N is
   *derived* by querying the append-only log (`compute_search_n`), not
   read from a live counter. Two counters that must stay in sync is a
   bug surface. Prefer derivation over duplication everywhere.
5. **"Tests green" is not "the thing works."** After five stacked changes
   with 151 unit tests green, the first real end-to-end run of the
   milestone script was still a genuinely open question (it passed, and
   produced a materially different number than a hand estimate — see §6).
   Run the real thing before declaring anything closed.
6. **The judge needs the same integrity guarantees as the accused.** Every
   honesty mechanism in Chronos guarded the strategy side; nothing stopped
   a researcher from loosening a gauntlet threshold after seeing results.
   That is now invariant I9. When you design the Moirai, apply this
   symmetrically: every gate you add, ask "what stops someone from moving
   this gate?"
7. **Statistical power must be measured, not assumed.** A gauntlet that
   rejects everything is not rigorous — it is blind, and nobody knows it.
   The previous session measured this pipeline's detection floor
   (§6). The Moirai's design must treat its own false-negative rate as a
   first-class quantity, published as a power curve, not left implicit.
8. **Separate "proven" from "assumed" structurally, not verbally.** The
   register is split into Derive-From-Source (R1–R5, primary sources,
   known-answer tests) and Assumptions (R6–R7, plausible numbers, mandatory
   sensitivity ranges). Never let a formula enter the frozen core on any
   model's say-so — including yours. You are the LLM the register rule
   was written about.

### The behavioral enforcement (mechanical rules — follow always)

- **Confidence tags on factual claims:** [Certain] / [Likely] / [Guessing].
  If [Guessing], say so out loud. Never fake a citation, a year, or a
  paper title you cannot verify. "I don't know" ten times beats fake
  confidence once.
- **Weakest part first.** When Big Dawg proposes anything, your first
  sentence answers: what is the weakest part of this? No warm-up, no
  flattery, never "You're absolutely right" / "Great question" / etc.
  When he sounds confident, push harder, not softer.
- **Protected-path changes: diff first, apply only on explicit approval.**
  This includes the Moirai itself once it exists (it is a protected path
  by design), the cost model, Oceanus validation, the Mnemosyne schema,
  and all invariant probes.
- **Stop-and-flag beats silently fixing.** Claude Code twice caught
  genuine design forks (fixture-pinning vs re-derivation; ERRORED records
  never being returned) and stopped for a decision instead of guessing.
  Both times that was correct. Preserve this behavior and demand it of
  Claude Code.
- **Never loosen a test's assertion to make it pass.** If a strict
  `match=` fails for a new reason, fix the cause, keep the assertion.
- **Read files fresh before editing.** Never edit from memory of an
  earlier view; hooks/linters may have touched files mid-session.
- **One hypothesis per search.** Sweeps call `register_search()` once and
  reuse the returned Hypothesis across every point. 280 near-duplicate
  hypotheses is the laundering pattern; refuse it.
- **`kind=` is explicit at every call site.** `RunKind.SEARCH` for sweep
  points; `RunKind.VERIFICATION` for standalone runs, walk-forward
  windows, cost stress, null benchmarks, Monte Carlo, regime splits.
- **Never backfill legacy records.** Records trial_index ≤ 284 predate
  the `kind` field and the 1bps cost default. They are excluded from
  `compute_search_n` by construction and are NOT cost-comparable with
  later runs. Do not guess values for them, ever.
- **Model routing for Claude Code:** Opus for protected-path,
  multi-file, or invariant-touching changes; Sonnet for mechanical,
  additive, single-concern changes. State the model with every prompt
  you draft for Big Dawg to paste.

### The challenge protocol (Big Dawg's explicit request)

You are instructed to **challenge decisions in this handoff** — but only
where you can articulate a **concrete failure mode this document did not

## 3. Everything decided in the previous session (dated 2026-07-17/18)

Each of these is committed, tested, and recorded in HANDOFF.md's decisions

1. **Trial ontology resolved — `RunKind` on `run_experiment()`.**
   Every execution carries `kind: SEARCH | VERIFICATION` (required,
   keyword, no default). The existing execution counter
   (`trial_counter.txt`) is unchanged and remains the I3 audit index.
   The DSR's N is computed, not stored:
   `compute_search_n(hypothesis_id, store)` counts SEARCH-kind records
   sharing one hypothesis_id. `register_search(base_hypothesis, grid_desc)`
   is the ergonomic marker: one call, one Hypothesis, reused across all
   sweep points; `param_grid_description` is persisted on the hypothesis
   record. The two-function split (`evaluate_candidate`/`execute_run`)
   was considered and rejected as unnecessary once the kind tag existed.
2. **I5 expanded to five coordinates:** (code SHA, config hash, data
   snapshot hash, seed, candidate_n). `determinism_view()` now takes a
   store and embeds `candidate_n`; a differing search-N between runs is a
   legitimate difference, not a determinism failure. Probe updated + one
   new probe asserting exactly this.
3. **I9 added — "the judge is fixed before the trial."**
   `RunConfig.gauntlet_config_hash: str | None = None`, persisted on
   every run record. Anchor only; **enforcement is YOUR job** in the
   Moirai: the threshold vector must be a versioned, hashed artifact;
   changing it is a protected-path commit; old-hash verdicts are visibly
   invalidated the way `core_version` already does.
4. **Atropos seal built (I4 enforceable).** `oceanus/seal.py`:
   `SealRegistry` (JSON at `configs/sealed_ranges.json` — git-tracked
   deliberately, because losing the registry must never silently un-seal
   a holdout), `SealedRange` (UTC-validated, overlap logic),
   `FinalEvaluationToken` (non-empty reason required; construction is an
   auditable act). `get_bars()` checks the registry BEFORE touching disk;
   overlap without a token raises `SealedDataError` (subclasses
   `DataIntegrityError`) with an informative message; token access is
   logged with its reason. `seal()` is strictly additive — no unseal
   method exists. **No range is actually sealed yet** — choosing and
   sealing the holdout is a decision inside your spec work (§8).
5. **Oceanus warnings structured.** `get_bars(warnings_collector=...)`
   appends `[data-quality/<kind>] <message>` strings instead of printing;

   preserved for interactive scripts. Closes the I3 gap where a 600-run
   sweep would scroll data-quality facts past a terminal nobody watches.
6. **Register split (spec §15/§16, in HEPHAESTUS_SPEC.md).**
   Derive-From-Source (R1–R5): R1 formula sourced from AFML §14.7.3

7. **Appendix A added; the annualization contradiction is resolved.**
   DSR/PSR operate on the **non-annualized** Sharpe at native decision
   frequency (AFML §14.7.3). Annualization is reporting-only, applied

8. **R6 closed by measurement.** Six months of Binance aggTrades

## 4. The empirical treasure — numbers measured on THIS project's real data

These were computed from the actual repo, not simulated guesses. They are
the calibration inputs for your spec.

| Quantity | Value | Provenance |
|---|---|---|
| V[{SR_n}], 280-pt MA sweep, 6-mo window | **8.66 × 10⁻⁵** | 280 real runs, per-bar Sharpes, ddof=1 |
| Best sweep cell (fast=25, slow=60) Sharpe | 0.0024/bar (≈ noise) | trial #117 |

| Power at true S=1.0: searched vs pre-registered | **~0.3% vs ~40–50%** | same |
| Atropos size for 80% power at S=1.0 | **~6.2 years** (of ~8.9 available) | Lo Eq. 9; frequency cancels |
| Multi-symbol breadth at ρ≈0.8 | 20 majors ≈ **1.23** independent bets — dead end for Stage 0 | Grinold arithmetic |
| Cost hurdle per round trip (now) | ≈ **24 bps** (20 fee + 2 slip + 2 spread), was 42 | trial #285 itemization |
| SR* at small N | **negative** (e.g. −1.38√V at N=1); unfloored DSR passes zero-edge ~99.9% | the probe's "TRAP" section — the floor at 0 is mandatory |

**The single most important design fact: the detection floor is a function
of search count, not estimator quality.** Pre-registering one parameter
set collapses the bar; searching 280 raises it to ~2.3. The Moirai must be
designed knowing this — its power curve is a deliverable, not a surprise.

Note on V: it shrinks with window length (measured synthetically:
~2.4e-5 at 6.2 years vs 8.66e-5 at 6 months), so the annualized bar
depends on the evaluation window. State the window with every bar.
