## For the gate

- **Trap: a dispatched builder has no shipped way to check the lock.**
  `specs/README.md` builder rule 3 says "check the lock is still yours
  (`/tick` does both)", but `/chronos-tick` only claims before dispatching and
  releases after; the builder, a separate session, pushes in between with no
  command for `still_mine` or `renew`. This builder wrote its own helper over
  `lock.py`. Every unattended builder will otherwise improvise one, or skip the
  check. Option for the founder: a `loop_cli.py still-mine --build <id>` and
  `renew` subcommand (`.claude/` is founder-owned, so it needs a spec), or
  accept that the dispatched builder improvises.
- **Trap: a cloud session's Postgres starts on password auth, and an
  unattended session may not change it.** `test_postgres_select_1` needs trust
  auth; earlier reviewers edited `pg_hba.conf` by hand; here the permission
  system refused it. Options: set trust auth in the cloud environment's setup
  so every session starts with it; or record that CI is the authority for this
  one test in unattended sessions.
- **Trap: GitHub's GraphQL is refused from a cloud session,** so `gh pr
  create` fails. The draft pull request was opened with
  `gh api repos/…/pulls -F draft=true`, as the refusal's own text advises; the
  same text names `…/pulls/<n>/ccr/ready_for_review` as the route for marking
  it ready, which this builder uses after pushing this commit.
- **Numbering:** the spec's "builder rule 7" (finish) is `specs/README.md`'s
  numbering; the builder agent file numbers the same rule 9. Same rule, no
  conflict.
- Nothing for the status board, `CODEBASE.md` or `COMPONENTS.md`. The ticks,
  their times and what each cost are B05B's to record.
