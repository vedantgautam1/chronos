## Findings as relayed

### 1. The six key tests asserted too weakly — no `match=`

The six known-answer tests for refused dict keys used a bare
`pytest.raises(TypeError)`. Spec Deliver 1 requires the `TypeError` to name the
offending key's type, and a bare `pytest.raises` does not check that: the tests would
still pass if the code raised a `TypeError` for an unrelated reason, or stopped naming
the type altogether. Reviewer rule 4 names "a test that asserts something weaker than
the spec" as a thing to look for.

### 2. The error message was not pinned

Same root cause as finding 1, recorded separately at the time. Nothing in the suite
pinned the text of the `TypeError`, so the "naming the offending key's type" half of
Deliver 1 was unverified by any test.

### 3. The sort-line change was not declared

The dict branch's sort expression changed from
`sorted(obj.items(), key=lambda kv: str(kv[0]))` to `sorted(obj.items())`. Spec Deliver
2 says everything else in `canonical.py` is unchanged, and the report at the time
declared no deviations.
